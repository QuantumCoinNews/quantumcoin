# HTTP endpoint ownership and schema evidence

## Owners

| Service | Runtime | Authority |
| --- | --- | --- |
| QuantumCoin node | Root main.go and node_app_router.go | QC chain, protected balance and signed transaction API, miner templates and commits, network and node security. |
| Telegram Game | telegram_game.runtime:app | Telegram identity, gameplay sessions, scores, TGWT ledger and withdrawals. QC bridge calls are client calls to the node. |
| Native wallet | cmd/wallet | User wallet and local signing. It consumes the node API. |
| Operator dashboard | release/qc_kontrol_paneli | Loopback status views and node monitoring reads. Telegram settlement administration remains inside the game service. |

The node route register is [node-endpoints.csv](node-endpoints.csv). The enclosing
owner for every row is the root QuantumCoin node. Response names refer to Go
DTOs or the named source projection. For a typical node error, see the shared
JSON writer in node_app_http.go. The /api and /api/ boundaries return JSON 404
for unknown paths. The root static embed serves GET and HEAD and handles no
API paths. The protected observer API enforces its independent capability
allowlist, including the signed NFT receipt read expressed as POST.

The [Telegram register](telegram-endpoints.json) records real ASGI methods,
request parameters, body definitions and OpenAPI components. Its auth column is
derived from the same player boundary policy used by the application. Dynamic
responses include literal keys and HTTP codes when directly declared in the
handler. Named wire models live in `telegram_game/endpoint_response_contracts.py`;
existing identity/ownership models remain in `response_contracts.py`. The register
contains OpenAPI security alternatives as well as request and response components.
An unknown new JSON handler without a contract fails registration. The models
describe existing responses without filtering or coercing runtime payloads.

`typedSuccessSchema=false` is expected for static/HTML responses and error-only
retired/unavailable operations. Those operations advertise their actual error
status rather than a fictional 200 success. Some legacy handlers return an
`ok:false,error:string` body with HTTP 200; clients must inspect both status and
body. 422 has two forms: the outer identity/body guard's error envelope and
redacted FastAPI validation issues. No request input is echoed in the latter.

Integer TGWT buckets, QC decimal/atom strings, wallet snapshots and mining runs
have explicit wire types. Historical rows and versioned policy/evidence documents
use declared JSON extension objects. Their internal policy is owned by the source
module or Go node; this register does not invent a second consensus or payment
validator. The two node health/balance forwarding routes explicitly identify that
ownership with `schemaKind=node-owned-json-document`. These JSON document fields
are intentionally extensible; generated clients should not assume extra fields
are local typed DTOs. No schema indicates that NFT final assets, live social proof
or a BSC settlement adapter is ready or enabled.

Run the drift checks with the locked Telegram environment and Go toolchain.

    python scripts/export_game_endpoints.py --check
    go test . -run TestNodeEndpointInventoryCoversCanonicalMux -count=1

Wire acceptance additionally runs `telegram_game/tests/test_endpoint_schemas_v1.py`
through the existing isolated discovery adapter. It validates real ASGI responses,
unauthorized routes and existing identity/wallet/ledger/NFT/social integration
scenarios. NFT scenarios require the public test contract generated by node
`TestNFTVerifiedLifecycleContractV1`; they fail rather than skip when it is absent.

## Credentials and signing

- Node operators and server bridges use X-QC-API-KEY or a node bearer credential.
  The native wallet, CLI miner, operator panel and Telegram bridge use direct
  requests and reject redirects. Remote credential-bearing HTTP requires HTTPS.
- Telegram players verify initData and use the issued session bearer. Operator
  endpoints use the separate Telegram operator credential. OAuth callbacks
  verify provider state and code. Static pages and the listed public game routes
  require no player session.
- The browser balance viewer is a read-only companion. The embedded root page is
  a public landing plus a separate operator mining page. Neither receives wallet
  keys. The native wallet or CLI signs locally. Telegram links a QC wallet by a
  signed, expiring, single-use challenge and relays a signed transaction envelope.
- Removed root gameplay paths use the unknown-route boundary. The Telegram
  leaderboard lives at GET /api/leaderboard/top. The former standalone Go API
  has no listener or production router.
